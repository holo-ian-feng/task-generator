Run the full test suite for the temporal worker, generate a structured markdown report, and commit it to the repository.

## Steps

1. **Run the test suite** by executing the following command from the project root. Capture all output — you need the full pytest output including PASSED/FAILED/XFAILED lines and the summary line at the bottom.

```
cd temporal && python -m pytest tests/ -v --tb=short 2>&1
```

If `pydantic` or other dependencies are missing, first run:
```
pip install -e "temporal[test]"
```
then re-run pytest.

2. **Parse the output** and extract:
   - Total counts: passed, failed, error, xfailed, xpassed
   - Duration (seconds)
   - For each FAILED test: test node ID + the captured traceback/short tb
   - For each XFAILED test: test node ID + the `reason=` string
   - For each XPASSED test: test node ID (these need immediate attention — the xfail mark must be removed)
   - Any collection errors

3. **Determine the report directory**. Use the `temporal/test-reports/` directory (relative to the project root). Create it if it does not exist.

4. **Write the report** as a markdown file named `YYYY-MM-DD_HH-MM-SS.md` using today's date and current time (get these from the system via a shell command like `date` or PowerShell `Get-Date`). The report must contain:

```markdown
# Test Report — YYYY-MM-DD HH:MM:SS

## Summary

| Result   | Count |
|----------|-------|
| Passed   | N     |
| Failed   | N     |
| Errors   | N     |
| XFailed  | N     |
| XPassed  | N     |

**Overall: PASS / FAIL**  
Duration: X.XXs

> PASS when failed=0 and xpassed=0. FAIL otherwise.

---

## Failures

*(omit this section if there are no failures)*

### `test_node_id`

```
<short traceback>
```

---

## Known Defects (XFailed)

These tests document confirmed bugs. They are expected to fail until each defect is fixed.
When fixed, the test will show as XPASS — remove the `xfail` marker at that point.

| Test | Reason |
|------|--------|
| `test_node_id` | reason string |

---

## Unexpected Passes (XPassed) — ACTION REQUIRED

*(omit this section if there are no xpasses)*

These tests were marked `xfail` but passed — the underlying defect has been fixed.
**Remove the `@pytest.mark.xfail` decorator from each test listed here.**

| Test |
|------|
| `test_node_id` |

---

*Generated by `/run-tests` skill*
```

5. **Commit the report** to git:
   - Stage only the new report file: `git add temporal/test-reports/<filename>.md`
   - Commit with message: `test: add report YYYY-MM-DD HH:MM:SS — N passed, N xfailed, N failed`
   - Do NOT push unless the user explicitly asks to push.

6. **Print a summary** to the user showing: overall PASS/FAIL, counts, the path to the report file, and the git commit hash.

## Notes

- The `temporal/test-reports/` directory should be committed too (add a `.gitkeep` if it is empty after prior runs).
- If pytest exits with code 5 (no tests collected), treat that as an error and report it clearly.
- xfailed tests are NOT failures — they are documented known defects and must never be counted as failures.
- xpassed tests ARE failures — flag them prominently.
